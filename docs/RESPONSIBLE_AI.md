# Compliance & Responsible AI Statement

OpsLedger AI is a human-reviewed workflow assistant, not an autonomous credit or eligibility decision-maker. The Future Caribbean demonstration uses synthetic business records created for this repository. The interface warns users not to upload real identity, banking, tax, health, or client documents. A production deployment would need a documented lawful basis for processing, purpose limitation, consent or contract controls where applicable, retention rules, regional hosting decisions, and review against the laws of each operating jurisdiction.

The system separates deterministic validation from model-generated assistance. Code checks required fields and documents, duplicate identifiers and files, arithmetic consistency, document recency, file safety, currency and identity conflicts, and allowed workflow transitions. The language model summarizes the resulting evidence, explains unresolved findings, drafts a request for missing information, and proposes a workflow route. It cannot approve financing, reject an applicant, transfer funds, resolve an identity conflict, close a case, or send an external message. A human reviewer supplies a rationale for consequential actions, and the system records the decision and any override.

Model input is limited to a canonical case record, extracted fields, findings, document metadata, and a small versioned demonstration policy. The agent uses five typed, read-only context tools. Its strict output schema rejects extra fields, and application checks reject unknown citations, unknown finding IDs, or a proposed route that conflicts with deterministic code. One repair attempt is allowed. OpsLedger stores tool summaries, structured output, citations, provider identity, latency, and concise reviewer-facing reasons; it does not store hidden model reasoning.

The workflow excludes protected characteristics and does not calculate creditworthiness. Its readiness score is a visible weighted checklist for package completeness. Reviewers can inspect the source locator behind extracted fields, record a resolution note, correct evidence, and rerun processing. Model limitations remain visible in every recommendation.

Files are allowlisted by extension, MIME type, and content signature; filenames are sanitized; uploads are size-, page-, and row-bounded; and evidence is stored privately. Secrets remain server-side. Audit records are protected from update or deletion in both application code and database triggers. Public logs and errors use safe messages and correlation IDs rather than document contents or stack traces.

The MVP does not claim compliance with GDPR, CCPA/CPRA, the EU AI Act, banking regulation, or Caribbean privacy law. Production adoption would require tenant authentication, a data-protection impact assessment, vendor and model-risk review, malware scanning, security testing, incident response, retention/deletion automation, accessibility validation, and local legal advice. Customers should be able to select an acceptable data region, retention period, and model-processing policy before real records are handled.
